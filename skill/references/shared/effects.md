# AI 粒子效果编排 Prompt

> 用于 AI 生成 pet.json 时的 skill prompt 片段。
> AI 在编排完动作后，决定是否为宠物启用粒子装饰效果，并通过预设 + 可选覆写的方式进行编排。

---

## 架构概览

粒子效果采用 **引擎内置默认预设 + 宠物级覆写** 的方案：

```
desktop-pet 内置 default_effect_presets.json   ← 9 套通用预设（随二进制，AI 不写）
{accountPetHome}/user/pet.patch.json            ← actions.*.effect 引用预设名 + 可选 effectOverrides
{accountPetHome}/runtime/pet.json               ← 合并结果（只读）
```

可选兼容：若 `{runtime}/effect.json` 或 official 层仍带该文件，同名 key 会覆盖内置默认。

其中 `{accountPetHome}` = `{petRoot}/accounts/{accountId}/pets/{petId}`。

**AI 的核心任务**：在写入 `user/pet.patch.json` 时，为原子动作添加 `"effect": "预设名"`，以及按角色风格添加 `effectOverrides`。  
`enrich_pet_patch.py` 会按关键词为**缺失**的 atomic `effect` 自动补全；AI 应校对语义并补 `effectOverrides`（若需要角色特色 emoji）。

参考 Desktop Goose、Kirby Desktop Pet、Pixel Agents、VPet 等主流桌宠产品的粒子设计模式：


| 场景       | 主流效果模式     | 典型 emoji | 设计意图         |
| -------- | ---------- | -------- | ------------ |
| 睡眠/打盹    | 缓慢上飘的 Z 符号 | 💤 😴    | 静谧、轻柔，强调安宁氛围 |
| 开心/兴奋    | 快速弹出的星星和音符 | ✨ 🌟 🎵  | 活力四射、情绪外溢    |
| 悲伤/失败    | 缓缓下滑的泪滴    | 💧 💦    | 低落、沉重感       |
| 行走/跑步    | 脚底扬尘       | 💨       | 速度感、动态反馈     |
| 待机/发呆    | 极低频的环境微粒   | 🍃 🦋    | 若有若无，营造生活感   |
| 嬉戏/翻滚    | 散射的星星和音符   | ✨ 🎵 💫  | 活泼好动、欢快氛围    |
| 微表情/细微动作 | 头顶微弱闪光     | ✨ 💫     | 含蓄的情感表达      |
| 眩晕/惊吓    | 快速散射的星星    | 💫 ⭐ ❗   | 慌张、头晕目眩      |
| 喜爱/抚摸    | 上飘的爱心      | ❤️ 💕 💖 | 温暖、被爱的满足感    |


**核心设计原则：**

1. **效果是反馈而非装饰**：粒子应强化动作语义，让用户无需看动画名就能理解角色状态
2. **频率与能量匹配**：高能动作（开心、嬉戏）用短间隔密集粒子；低能状态（睡觉、待机）用长间隔稀疏粒子
3. **少即是多**：3-5 秒内屏幕上同时可见 1-3 个粒子已足够
4. **时机比数量重要**：一个恰到好处的粒子 > 十个泛滥的粒子
5. **宁缺毋滥**：找不到合适预设时不加 effect，比强行匹配一个不合适的预设更好

## AI 决策流程

### Step 1：是否需要粒子

- 大多数桌宠适合粒子效果（增加趣味和生动感）
- 极简风、纯功能性角色可跳过
- 不确定时不添加 effect 字段即可，系统不会报错

### Step 2：为每个原子动作选择预设

#### 2.1 预设表

9 个可用预设（引擎内置，与 `default_effect_presets.json` 一致）：


| 预设名       | 场景  | 默认 emoji | 方向      | 关键词（action name 含以下语义时匹配）            |
| --------- | --- | -------- | ------- | ------------------------------------ |
| `idle`    | 待机  | 🍃 🦋    | scatter | 发呆、站立、待机、放松、休息（非睡觉）                  |
| `sleep`   | 睡眠  | 💤 😴    | up      | 睡觉、打盹、打瞌睡、入睡、关机、休眠                   |
| `happy`   | 开心  | ✨ 🌟 🎵  | up      | 开心、兴奋、庆祝、成功、跳舞、欢呼、胜利、得意、喷火、施法、充能、发光  |
| `sad`     | 悲伤  | 💧 💦    | down    | 难过、害怕、失败、沮丧、哭泣、受伤、生病、报错、受挫           |
| `walking` | 行走  | 💨       | scatter | 走路、跑步、移动、飞行、游泳、滑行、巡逻、漫步              |
| `playful` | 嬉戏  | ✨ 🎵 💫  | scatter | 翻滚、踢腿、嬉闹、撒娇、打闹、调皮、打翻、吃东西、抓挠、追逐       |
| `micro`   | 微表情 | ✨ 💫     | up      | 眨眼、摇尾巴、招手、点头、摇头、打哈欠、伸懒腰、抖耳朵、打字、阅读、思考 |
| `dizzy`   | 眩晕  | 💫 ⭐ ❗   | scatter | 被拎起、被甩、自由落体、撞墙、晕倒、触电、爆炸、警报、出错死机      |
| `love`    | 喜爱  | ❤️ 💕 💖 | up      | 被抚摸、喜爱、撒娇求抱、脸红、示爱、求食、讨好              |


#### 2.2 决策流程图

```
读取 action 的 name（中文名）
  │
  ├─ name 含「睡/眠/盹/关机/休眠」─────────────→ sleep
  ├─ name 含「走/跑/飞/游/滑/移动/巡」──────────→ walking
  ├─ name 含「开心/兴奋/庆祝/成功/跳舞/欢呼」───→ happy
  ├─ name 含「难过/失败/伤/哭/怕/沮丧/病」──────→ sad
  ├─ name 含「翻/滚/踢/闹/调皮/吃/抓/追」──────→ playful
  ├─ name 含「摸/爱/抱/脸红/撒娇求/讨好」──────→ love
  ├─ name 含「拎/甩/落/撞/晕/电/炸/警/死机」──→ dizzy
  ├─ name 含「眨/摇/招/点头/伸/打哈欠/打字」──→ micro
  ├─ name 含「发呆/站/待机/放松」────────────────→ idle
  │
  └─ 以上均不匹配 → 用「能量-情感矩阵」判断（§2.3）
```

#### 2.3 兜底：能量-情感矩阵

当 action name 不含上述任何关键词时，用两个维度判断：

**维度 1 — 情感极性：** 这个动作表达的是正面/中性/负面情绪？
**维度 2 — 能量级别：** 这个动作的运动幅度是低/中/高？


|           | 低能量     | 中能量       | 高能量       |
| --------- | ------- | --------- | --------- |
| **正面**    | `idle`  | `happy`   | `happy`   |
| **中性**    | `micro` | `walking` | `playful` |
| **负面**    | `sad`   | `sad`     | `dizzy`   |
| **被动/受力** | `sleep` | `dizzy`   | `dizzy`   |


**仍然无法判断 → 不添加 effect 字段**（这比强行匹配一个不合适的预设更好）。

#### 2.4 通用匹配规则

- **transition 动作（过渡）**：不加 effect（过渡通常很短，粒子来不及展示）
- **行为驱动的 atomic**（如 hang、falling）：可按语义挂 effect（如 `dizzy`）
- **多个预设都可能匹配时**：选**语义最贴近**的那个。如果拿不准，优先选更低调的（如 `micro` 优先于 `happy`）
- **loop=false 的短动作**：优先选 `micro`（粒子需要与短动画时长匹配）

### Step 3：是否需要覆写

**大多数情况不需要覆写**，预设已提供合理的默认参数。

仅当需要给宠物注入角色特色时，在 `pet.json` 的 `effectOverrides` 中添加覆写，**只写需要覆盖的字段**：

```json
{
  "happy": {
    "emojis": ["✨", "🌟", "🐾", "🌸", "🎵"]
  },
  "playful": {
    "emojis": ["🐾", "✨", "🎵", "💫"]
  }
}
```

**典型覆写场景**：

- **自定义 emoji 调色板**：最常见，为角色选择专属 emoji（如猫用 🐾，樱花角色用 🌸）
- **节奏调整**：活泼角色缩短 `intervalMs`，慵懒角色加长
- **不覆写也完全可以**：系统用预设默认值运行

## 创意指导：emoji 调色板

为角色挑选一组统一风格的 emoji，然后在 `effectOverrides` 中分配到各预设：


| 角色风格   | emoji 调色板示例                           |
| ------ | ------------------------------------- |
| 猫/可爱   | 🐾 💖 ✨ 🌟 🌸 🦋 🍃 💤 😾 💧 😵‍💫 💫 |
| 科技/电子  | ⚡ 💫 🔋 💡 ❄️ 🌀 💨 💤 🔥 💥 ⚠️       |
| 樱花/浪漫  | 🌸 🌺 💖 ✨ 💎 🎀 🌙 💤 💧 🦋          |
| 火焰/暗黑  | 🔥 💥 💢 👻 🔮 💜 🖤 💤 💀 ⚡          |
| 狗/活力   | 🐾 🦴 ✨ 🎾 💨 🌟 🎵 💤 💧 💫          |
| 兔/温柔   | 🥕 🌷 💖 ✨ 🌸 🎀 💤 💧 🌟 🍃          |
| 龙/奇幻   | 🔥 ✨ 💎 🐲 💫 🌟 🌙 💤 💧 ⚡           |
| 机器人/科幻 | ⚡ 🔧 💡 🔋 💫 🌀 💤 ⚠️ 🔥 💥          |


**关键原则**：

- 同一角色的所有 emoji 应来自同一个调色板
- 正面情绪用**明亮/温暖** emoji，负面用**暗淡/冷** emoji
- 每个预设覆写 2-5 个 emoji，不要每个预设都用相同集合
- **角色标志 emoji**（如猫的 🐾、科技的 ⚡）应出现在高频预设中（happy、playful）

## 参数详解

以下是内置预设和 `effectOverrides` 覆写中可用的全部参数：

### 基础参数


| 参数           | 类型       | 必填  | 范围                              | 默认值         | 说明                                    |
| ------------ | -------- | --- | ------------------------------- | ----------- | ------------------------------------- |
| `scene`      | string   | ✅   | —                               | —           | 效果场景描述（仅预设文件需要）                       |
| `emojis`     | string[] | ✅   | 2-5 个                           | —           | emoji 池，每次随机选取一个生成                    |
| `intervalMs` | number   | ✅   | 200-60000                       | —           | 两次粒子生成之间的间隔（ms）                       |
| `lifetimeMs` | number   | ✅   | 100-10000                       | —           | 单个粒子从生成到消失的总时长（ms）                    |
| `distance`   | number   | ✅   | 0.05-0.9                        | —           | 粒子运动距离，**画布短边的比例**（0.3 = 走 30% 的画布短边） |
| `sizeScale`  | number   | ✅   | 0.1-3                           | —           | 粒子大小缩放系数（1.0 = 基准大小）                  |
| `direction`  | string   | 否   | `"up"` / `"down"` / `"scatter"` | `"scatter"` | 粒子运动方向                                |
| `originY`    | number   | 否   | 0-1                             | 0.4         | 粒子生成的 Y 坐标（0=头顶 1=脚底）                 |


> `**effectOverrides` 中所有参数都是可选的**，只写需要覆盖的字段。

### 内置随机性（不可配置）

系统为视觉自然度内置了以下随机因素，无需也无法通过参数控制：


| 随机因素    | 具体行为                            |
| ------- | ------------------------------- |
| 粒子大小    | 在 `sizeScale` 基础上 ×0.6~1.4 随机   |
| 运动距离    | 在 `distance` 计算的距离上 ×0.7~1.3 抖动 |
| 横向漂移    | 运动过程中有轻微的水平偏移                   |
| 生成 X 位置 | 在画布中心附近 ±7.5% 宽度范围内随机           |


### 运动物理模型

粒子运动基于 **easeOutCubic 缓动曲线**（前快后慢），淡出从 65% 寿命开始。

内部速度由系统自动计算：`speed = distance × canvasShortSide / lifetimeMs`

AI 只需关心 `distance`（走多远）和 `lifetimeMs`（活多久），**不需要手动计算 speed**。

## 安全说明

- 系统内置参数防护，极端值会自动钳制到安全范围，空 emojis 的规则会被跳过
- **transition 动作自动跳过**：`resolveEffectsFromManifest` 只处理 `kind !== 'transition'` 的 state，即使误配 `effect` 也不会生效
- **同屏粒子上限 4 个**（`ParticleConfig.maxVisible`，可配置），各预设稳态 ~1 个粒子
- 大胆编排，追求效果优先

### 示例 1：慵懒的三花猫

角色关键词：猫、慵懒、可爱、毛茸茸
emoji 调色板：🐾 💖 ✨ 🌟 🌸 🎵 🍃 🦋 💤 😴 💧 💦 💫 😵‍💫

**pet.json 中的 effect 字段：**

```json
{
  "idle": { "name": "发呆", "effect": "idle" },
  "happy": { "name": "开心循环", "effect": "happy" },
  "belly_roll": { "name": "翻肚皮踢腿", "effect": "playful" },

  "wave": { "name": "打招呼", "effect": "micro" },
  "hang": { "name": "悬垂拖拽", "effect": "dizzy" },
  "falling": { "name": "自由落体", "effect": "dizzy" }
}
```

**pet.json 中的 `effectOverrides`：**

```json
{
  "happy": { "emojis": ["✨", "🌟", "🐾", "🌸", "🎵"] },
  "walking": { "emojis": ["💨", "🐾", "✨"] },

```

**决策思路**：翻肚皮="翻"→ playful；眨眼="眨"→ micro；拖拽=被动受力 → dizzy；🐾 出现在 happy/walking/playful 强化猫身份。
